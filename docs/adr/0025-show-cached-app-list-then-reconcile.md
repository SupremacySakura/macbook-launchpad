# 启动时先展示应用清单缓存，再用扫描结果按差异更新

Status: accepted

应用清单（不含图标）以带版本号的 JSON 快照持久化到用户的 Application Support 目录。启动台在创建首帧之前同步读取缓存，因此有缓存时首个界面就包含应用项；同时仍在后台执行一次完整应用扫描。扫描完成后比较缓存与扫描结果中的新增、移除、元数据变化和顺序变化，只有 diff 非空时才替换界面状态，并把新的扫描结果写回缓存。扫描结果写入失败或缓存损坏都按“没有缓存”处理，不显示额外错误 UI。

理由：
- 后台扫描完成前就展示上次结果，消除重复唤起时的空白骨架屏
- 每次启动仍会全量扫描，安装、卸载或改名后的结果可以自动追上真实文件系统
- 显式 diff 避免清单未变化时无意义地替换 SwiftUI 状态，也能在排序变化时正确刷新
- 缓存只保存轻量元数据，不引入图标缓存、目录监听或后台守护进程

代价：
- 当应用刚被移动或删除时，缓存中的旧应用项可能短暂可见；点击这类过期项仍按现有策略静默失败，直到扫描完成将其移除
- 首次运行没有缓存时仍会显示现有加载占位
- 图标继续按页异步加载，因此缓存首屏中的图标可能短暂使用占位
